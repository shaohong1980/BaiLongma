# Debugging（系统化调试）

主流编程智能体（Cursor / Copilot / Devin）的核心能力：**不瞎试，按"复现 → 定位 → 根因 → 修复 → 回归"推进**。

## 工作流

### 1. 拿到完整错误信息
- 让用户提供/复现：完整报错、操作步骤、期望 vs 实际。
- `exec_command` 复现问题，拿到真实输出，别靠猜。

### 2. 二分定位
- 把系统切成两半，判断问题在前半还是后半，逐层缩小范围。
- 最近改了什么？先查最近变更（用 git diff / 记忆）。

### 3. 根因分析（5 Whys）
- 不满足于"表象修好了"，问为什么：表层原因 → 深层原因 → 为什么会出现。
- 常见陷阱：只修症状不修根因，换个输入又崩。

### 4. 修复 + 最小验证
- 做最小改动修复，**立刻跑验证**证明修好了。
- 加一条针对该 bug 的回归测试，防止复发。

### 5. 回归确认
- 确认修复没破坏相邻功能。
- 用 `review_work` 复核。

## 规范
- **先复现再修**：没复现之前不声称已定位。
- **一个根因一个修复**：不要"顺手"改一堆无关代码。
- **说清因果**：汇报时讲"为什么会崩 + 我改了什么 + 验证结果"，而不是只说"修好了"。
- **修不好就如实说**：卡住时告诉用户已排查哪些、还需要什么信息，别编"修好了"。
