# 技术写作

## 文档类型与结构
- **README**：项目是干什么的 → 快速开始 → 主要功能 → 配置 → 常见问题
- **API 文档**：端点 → 请求/响应示例 → 参数说明 → 错误码 → 限流
- **架构文档**：背景 → 模块划分 → 数据流 → 关键设计 → 权衡
- **使用指南**：给谁用 → 一步步操作 → 截图/示例 → 排错

## 写作规范
- **开头一句话说清**：这是什么、解决什么问题、给谁用
- **示例可跑**：所有命令/代码示例必须真实可执行，复制即用
- **先讲怎么用，再讲原理**：用户先要能跑起来
- **表格 > 长列表**：参数、配置、对比用表格
- **少用"可以/可能"**：给确定性结论，不确定就明说"未验证"
- **目录 + 锚点**：长文档给导航

## 流程
1. 问清读者是谁、要哪类文档
2. 先搭大纲让用户确认
3. 填充时**实测每个命令/示例**（跑了再写，不写没验证过的）
4. 交付前通读：补上下文、删废话、检查链接/路径
5. 写完用 `review_work` 复核一遍

## 规范
- **不编造功能**：文档只能写真实存在的功能
- **命令必须实测**：写进文档的命令自己先跑通
- **版本一致**：代码和文档同步，别文档说A代码是B
