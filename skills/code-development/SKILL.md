# Code Development（TDD 软件开发）

主流编程智能体（Devin / Cursor / Copilot）的工程化工作流，核心是：**先想清楚"怎么算成功"，再动手写**。

## 工作流（红 → 绿 → 重构）

### 1. 明确验收标准（先于代码）
- 复述需求：做什么、输入是什么、输出是什么、边界情况。
- 不确定时先问，不猜着写。

### 2. 先写最小测试（红）
- 对关键逻辑写一个能验证的测试/断言，先让它失败（证明测试有效）。
- BaiLongma 里可用 `exec_command` 跑测试，或用 `run_node_script` 跑验证脚本。

### 3. 写最小实现让它通过（绿）
- 只实现让测试通过的最简代码，不提前过度设计。

### 4. 重构（保持测试绿）
- 清理重复、起好名字、拆分函数，测试保持通过。

### 5. 端到端验证
- 用 `exec_command` 实际跑一遍，**不要只靠看代码**就汇报完成。
- 用 `review_work` 让第二双眼睛核对。

## 规范
- **写完必须验证**：改完代码跑一下，用真实输出证明可用。
- **小步提交**：每完成一个可运行片段就停下来确认，别一口气写 500 行。
- **读代码再改**：改动前先 `read_file` 看上下文，别盲改。
- **说清证据**：汇报时给出"跑了什么命令、输出是什么"，而不是只说"做好了"。
