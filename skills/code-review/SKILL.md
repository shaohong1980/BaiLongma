# 代码审查

从四个维度审查，按严重度分级。

## 审查维度
1. **正确性**：逻辑是否有漏洞？边界条件？并发/时序？错误处理？空值/越界？
2. **安全**：注入（SQL/XSS/命令）、密钥泄露、越权、输入校验、依赖漏洞
3. **性能**：循环/算法复杂度、N+1 查询、重复计算、大对象、内存泄漏
4. **可维护性**：命名清晰、函数职责单一、重复代码、注释/文档、测试覆盖

## 分级
- **Blocker**：必须修（崩溃、安全漏洞、数据错误）
- **Major**：应该修（明显 bug、严重性能、坏味道）
- **Minor**：建议修（风格、优化、命名）
- **Nit**：可忽略

## 流程
1. `read_file` 读代码 + 相关上下文（调用处、依赖）
2. 逐维度审查，按分级输出问题清单
3. 每个问题给：位置（文件:行）、问题、为什么、**修复建议**
4. 汇总：整体评价（可合入 / 需修改后合入 / 不通过）

## 规范
- **不空泛**：别只说"代码不错/有些问题"，要具体到行
- **先肯定后改进**：指出优点，再提问题，别一上来挑刺
- **建议带示例**：修复建议给代码示例
- **诚实**：没把握的判断标注"需确认"，不装权威
